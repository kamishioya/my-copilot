# requirementsフォルダ

このフォルダには、会話を通して確定した要件定義を格納します。

## 目的

- 「何を作るか」を整理する
- 機能要件、非機能要件、業務ルール、未確定事項を分離する
- 後続の `docs/basic-design/` と `docs/spec/` から参照できる状態にする

## 推奨ファイル

- `00-overview.md`: 背景、目的、ステークホルダー、成功条件
- `01-scope.md`: スコープ内、スコープ外、制約、前提条件
- `02-functional-requirements.md`: 機能要件一覧
- `03-non-functional-requirements.md`: 性能、可用性、セキュリティ、運用要件
- `04-business-rules.md`: 業務ルール、判定条件、例外条件
- `05-open-questions.md`: 未確定事項、確認待ち事項

## ルール

- 会話ログの全文保存ではなく、確定事項を構造化して整理する
- 未確定事項は必ず別ファイルに分ける
- 要件IDや用語を統一し、設計書から参照できるようにする
- 1ファイルに複数テーマを詰め込みすぎない

## 作成方法

- 要件定義を作成するときは `create-requirements` スキルを使う
