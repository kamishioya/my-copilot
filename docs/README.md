# docsフォルダ

このディレクトリに、要件定義、基本設計、詳細設計、実装計画を格納します。

## ディレクトリ構造

```
docs/
├── requirements/      # 要件定義。会話で確定した内容をテーマ別ファイルで整理
├── basic-design/      # 基本設計。画面一覧、DB定義、項目定義、IF定義などを分割管理
├── spec/              # 詳細設計
│   ├── screens/       # 画面単位の仕様
│   └── business-logic/# ビジネスロジック単位の仕様
└── plan/              # 実装計画書
```

## 運用方針

- `requirements/` は「〜システムを作りたい」から始まる会話で決まった内容を整理する場所です
- `basic-design/` はウォーターフォールでいう基本設計に相当し、1ファイル1テーマで管理します
- `spec/` は詳細設計に相当し、画面単位とビジネスロジック単位のファイルを分けます
- `plan/` は実装の進め方、フェーズ、検証手順を管理します

## 使い方

- 要件定義を作成するには `create-requirements` スキルを使用
- 基本設計を作成するには `create-basic-design` スキルを使用
- アーキテクチャ図や大きな設計判断を補強するには `architect` エージェントを使用
- 詳細設計を作成するには `create-spec` スキルを使用
- 実装計画を作成するには `create-plan` スキルを使用
