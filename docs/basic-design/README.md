# basic-designフォルダ

このフォルダには、ウォーターフォールでいう基本設計に相当する文書を格納します。

## 基本方針

- 1ファイル1テーマで管理する
- 画面一覧、DB定義、項目定義、インターフェース定義を別ファイルに分ける
- 要件定義を入力として、実装前に必要な構成・責務・データ・連携を明確化する

## 推奨ファイル

- `index.md`: 基本設計の目次と参照関係
- `system-overview.md`: システム概要、主要構成、アーキテクチャ図
- `screen-list.md`: 画面一覧、画面ID、利用者、遷移概要
- `database-definition.md`: エンティティ、テーブル、ERの要約
- `field-definitions.md`: 項目定義、属性、共通バリデーション方針
- `interface-definitions.md`: 外部・内部インターフェース、入出力、エラー方針
- `data-flow.md`: データフロー、処理順序、整合性ルール
- `architecture-decisions.md`: 設計判断、トレードオフ、リスク

## ルール

- 単一の総合設計書は作らない
- ダイアグラムは対象テーマのファイルに置く
- 詳細な画面仕様や詳細な処理手順は `docs/spec/` に書く

## 作成方法

- 基本設計を作成するときは `create-basic-design` スキルを使う
- Mermaid 図やアーキテクチャ判断が重い場合は `architect` エージェントを併用する
