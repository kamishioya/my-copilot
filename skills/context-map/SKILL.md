# コンテキストマップ

変更を実施する前に、コードベースと関連ドキュメントを分析してコンテキストマップを作成してください。

## 対象タスク

{{task_description}}

## 手順

1. このタスクに関連するファイルをコードベースから検索する
2. 直接的な依存関係（import/export）を特定する
3. 関連するテストを見つける
4. 既存コード内の類似パターンを探す
5. 関連する `docs/spec/`、`docs/design/`、`docs/plan/`、`README.md`、`db/`、`memory-bank/` の更新要否を判定する
6. 識別子生成、重複判定、checkpoint / resume / idempotency、screening / 分類ルールの変更が含まれるか確認する

## 出力フォーマット

```markdown
## コンテキストマップ

### 変更対象ファイル
| ファイル | 目的 | 必要な変更 |
|---------|------|-----------|
| path/to/file | 説明 | 変更内容 |

### 依存ファイル（更新が必要な可能性）
| ファイル | 関係性 |
|---------|--------|
| path/to/dep | 変更対象ファイルからXをインポート |

### テストファイル
| テスト | カバレッジ |
|--------|-----------|
| path/to/test | 影響を受ける機能のテスト |

### 参考パターン
| ファイル | パターン |
|---------|---------|
| path/to/similar | 参考にすべき実装例 |

### ドキュメント更新判定表
| 対象 | 判定 | 理由 | 想定アクション |
|------|------|------|----------------|
| docs/spec/... | 更新する / しない | 判断理由 | 変更点の要約 |
| docs/design/... | 更新する / しない | 判断理由 | 変更点の要約 |
| docs/plan/... | 更新する / しない | 判断理由 | 変更点の要約 |
| README.md | 更新する / しない | 判断理由 | 変更点の要約 |
| db/... | 更新する / しない | 判断理由 | 変更点の要約 |

### MemoryBank 更新判定表
| 対象 | 判定 | 理由 |
|------|------|------|
| memory-bank/activeContext.md | 更新する / しない | 判断理由 |
| memory-bank/progress.md | 更新する / しない | 判断理由 |

### リスク評価
- [ ] 公開APIへの破壊的変更
- [ ] データベースマイグレーションが必要
- [ ] 設定ファイルの変更が必要
- [ ] パフォーマンスへの影響の可能性
- [ ] セキュリティへの影響の可能性
- [ ] 識別子・キー生成規則の変更
- [ ] 重複判定・照合ルールの変更
- [ ] checkpoint / resume / idempotency ロジックの変更
- [ ] screening・分類・業務ルールの変更
```

**この判定表が埋まるまで実装に進まないこと。実装後は実際に更新するか、未更新理由を final answer に明記すること。**
